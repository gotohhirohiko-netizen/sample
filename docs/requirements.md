# 要件定義書(たたき台) — 個人用家計簿アプリ

version: 0.1(ドラフト) / 対象: 個人利用専用 iOSアプリ

## 1. 背景・目的

- 現在サブスクリプション型の家計簿アプリを利用しているが、使い勝手に不満があり自作したい。
- 銀行口座・クレジットカードの自動連携(オープンAPI経由)は、個人が電子決済等代行業の登録なしに実現するのは現実的ではないため、**半自動(手動ダウンロード+AIによる自動解析)**方式を採用する。
- 開発者本人のみが利用する前提とし、App Store配布は行わない(TestFlightまたは個人の実機ビルドのみ)。

## 2. 想定利用者・利用環境

| 項目 | 内容 |
|---|---|
| 利用者 | 開発者本人のみ(単一ユーザー) |
| 配布方法 | App Store配布なし。個人のApple Developerアカウントによる実機ビルド/TestFlight |
| 対応OS | iOS(バージョンは実装時に確定。SwiftDataを使う場合はiOS 17以降が前提) |
| 端末 | iPhone(iOSのみ、Android対応は行わない) |

## 3. 対象金融機関・カード

| 機関 | 種別 | 明細取得元 | 備考 |
|---|---|---|---|
| 三菱UFJ銀行 | 銀行口座 × 2口座 | 三菱UFJダイレクト(Web、PC版限定) | 口座ごとに個別の絞り込み・ダウンロード操作が必要 |
| 楽天カード | クレジットカード | 楽天e-NAVI(Web、PC版限定) | 請求月単位でのダウンロード |
| PayPayカード | クレジットカード | PayPayカード会員メニュー(Web) ※アプリ限定ではない | 請求月単位でのダウンロード |

## 4. 機能要件

### 4.1 明細インポート機能(半自動)

- 各金融機関ごとに、明細ページへの**ディープリンク**をアプリ内に保持する
- ユーザーが対象機関を選択すると、`SFSafariViewController` でその明細ページを開く
- ログイン・画面遷移・CSV/PDFダウンロードは**すべてユーザーが手動で操作**する(アプリ側での自動クリック・自動ログインは行わない)
- ダウンロードされたファイルは iOS標準の「ファイル」アプリに保存される想定
- アプリ内の手動インポート画面から、`UIDocumentPicker` でダウンロード済みファイルを選択して取り込む

### 4.2 データ抽出機能(AI解析)

- 取り込んだCSV/PDFファイルをClaude APIに送信し、以下の構造化データとして抽出する
  - 利用日 / 店名・利用先 / 金額 / **収入・支出の区分**
- 三菱UFJ銀行の明細は入金(収入)と出金(支出)の両方を含むため、抽出結果には`type`(収入/支出)を必ず含める。楽天カード・PayPayカードの明細は常に支出として扱い、返金等が発生した場合は**支出のマイナス値**として扱う(収入としては扱わない)
- 支出については、店名から**大カテゴリ・小カテゴリ**を自動推定し、抽出結果に含める(詳細は4.9カテゴリ自動判定・学習機能を参照)
- 支払方法(一括・分割等)の抽出は行わない(v1では対象外)
- 抽出は `output_config.format` によるJSON Schema指定の構造化出力を用いる(機関ごとの個別パーサーは実装しない)
- 抽出結果はプレビュー画面でユーザーが確認したうえで確定登録する(誤抽出の訂正・重複除外を人間が最終チェックする)

### 4.3 データ管理機能

- 取引データの一覧表示・編集・削除
- カテゴリの手動編集(カテゴリは4.6で設定する**大カテゴリ→小カテゴリの2階層の定義済み一覧からの選択式**とし、自由入力にはしない。予算実績の集計と齟齬が出ないようにするため)
- 手動でカテゴリを修正した場合、その店名とカテゴリの対応を学習し、次回以降の同一店名の取引には自動で反映する(詳細は4.9参照)
- 同一取引の重複取り込み防止(日付・店名・金額での重複検知 ※詳細は未決、7章参照)

### 4.4 日次収支リスト表示機能

- 概要: 選択した月の収支(収入・支出)を**日付ごとにグルーピング**して一覧表示する
- 詳細要件
  - 表示対象月を選択できる(前月・次月への切り替え)
  - 日付ごとにセクション分けし、当日の取引を一覧表示する
  - 各行に表示する情報: 金額(収入・支出を色や符号で視覚的に区別)、店名・摘要、**支払情報**(取り込み元の表示名。例:「楽天カード」「三菱UFJ 普通口座A」)
  - 各行タップで取引詳細・編集画面へ遷移する(4.3のデータ管理機能につながる)
- 備考: 「支払情報」は取り込み元の表示名のみとし、支払方法(一括・分割等)は含めない

### 4.5 月次収支確認機能(カテゴリ別 予算・実績)

- 概要: 選択した月について、カテゴリごとの**予算額と実績額(支出合計)**を一覧表示し、実績をタップするとその内訳(該当カテゴリ・該当月の取引一覧)を表示する
- 詳細要件
  - カテゴリを一覧表示し、各行に「カテゴリ名」「予算額」「実績額」「残額(予算-実績)または達成率(%)」を表示する
  - 予算超過時は視覚的に警告表示する(色分け等)
  - 実績額をタップすると、そのカテゴリ・その月に属する取引一覧(4.4のリストをカテゴリで絞り込んだもの)へ遷移する
  - 本機能の対象は支出カテゴリのみとする(収入の予実管理は対象外。収入合計は4.7でカバー)
  - カテゴリ未設定の取引は「未分類」として集計する
  - 本機能で表示する「カテゴリ」は**大カテゴリ単位**とする(小カテゴリ別の予算設定・集計は行わない)
- 関連: 4.6で設定した予算額を参照する

### 4.6 カテゴリ予算設定機能

- 概要: カテゴリごとに月次予算額を設定・編集できる
- カテゴリ体系: **大カテゴリ→小カテゴリの2階層構造**とする(例: 大カテゴリ「食費」の下に小カテゴリ「食料品」「カフェ」等)。初期カテゴリ一覧は8章「初期カテゴリ一覧(シードデータ)」を参照
- 詳細要件
  - 大カテゴリ・小カテゴリともに追加・編集・削除ができる(名称、表示順)。**カテゴリは後からいつでも追加できる**
  - 予算額は**大カテゴリ単位**で設定する(小カテゴリ単位の予算は設けない)
  - 初期状態で8章の初期カテゴリ一覧をあらかじめ登録しておく
  - 予算額を変更した場合、**過去月の予実評価には遡って適用しない**。変更は「変更した時点以降の月」にのみ適用する(過去に確認した予実表示が後から変わることはない)
    - 実装上は、予算額の変更履歴に「適用開始日」を持たせ、各月の予実評価時にはその月の時点で有効だった予算額を参照する

### 4.7 月次サマリー(対予算・対収入)

- 概要: 選択した月の収支総額を、**予算合計に対する割合**と、**収入合計に対する割合**の両方で確認できる
- 詳細要件
  - 当月の支出合計・収入合計・収支差額(収入-支出)を表示する
  - 「対予算」: 支出合計 ÷ 全カテゴリの予算合計(達成率%・残額)を表示する
  - 「対収入」: 支出合計 ÷ 収入合計(収入に対して何%使ったか)、または貯蓄額(収入-支出)を表示する
  - ホーム画面のトップに両方の指標を並べて表示する
- 備考: 収入データは主に三菱UFJ銀行口座の入金明細から取得する想定。カード明細の返金は収入に含めず、支出のマイナス値として扱う(4.2参照)

### 4.8 口座・カード管理機能

- 三菱UFJの2口座、楽天カード、PayPayカードをそれぞれ「取り込み元」として登録・管理
- 各取り込み元ごとにディープリンクURL・表示名を設定できる

### 4.9 カテゴリ自動判定・学習機能

- 概要: 明細抽出時に、店名からカテゴリ(大・小)をAIが自動推定し、ユーザーの手動修正を学習して次回以降に自動反映する
- 詳細要件
  - Claude APIによる抽出時、店名をもとに大カテゴリ・小カテゴリの候補を推定し、抽出結果に含める(例: 「イオン」→ 大カテゴリ「食費」・小カテゴリ「食料品」)
  - プレビュー画面・取引詳細画面でカテゴリを手動修正できる(4.3参照)
  - 手動修正した場合、「店名 → カテゴリ」の対応をアプリ内(端末内)に記憶する(学習マッピング)
  - 次回以降、同一店名の取引が取り込まれた際は、**学習マッピングを最優先で適用**し、Claudeによる推定より優先する
  - 優先順位: ①学習マッピング(店名の完全一致) → ②Claudeによる推定 → ③未分類
- 備考: 学習は端末内のデータ(店名→カテゴリの対応表)のみで行い、Claude API側にモデルとして学習させるものではない(5.1のセキュリティ方針とも整合)

## 5. 非機能要件

### 5.1 セキュリティ・プライバシー

- 銀行・カードのログインID/パスワードは**アプリ・バックエンドともに一切保存しない**(常に手動ログイン)
- Anthropic APIキーは iOS **Keychain** に保存する(平文保存・`UserDefaults`保存は禁止)
- Claude APIへ送信するのは明細データ(店名・金額・日付)のみで、認証情報は含まれない
- Anthropicの商用APIはデフォルトでモデル学習に利用されない(利用規約に基づく)
- 送信データはAnthropic側で不正利用監視目的の一定期間(目安30日程度)保持される点を認識しておく(一般的なクラウドサービス利用と同等のリスク)

### 5.2 コスト

- バックエンドサーバーは持たない(個人利用のみのため)。アプリから直接Claude APIを呼び出す
- 抽出モデルは基本 `claude-haiku-4-5` を使用し、精度に問題がある場合のみ `claude-sonnet-5` 等に切り替える運用とする
- 想定利用頻度(機関あたり月1回程度)であれば、APIコストは月あたり数十円以下に収まる見込み

### 5.3 可用性・保守性

- 各金融機関のサイトはUI変更が起こり得るため、**自動クリック等の自動化は行わず**、変更に強い設計(手動操作+AI抽出)とする
- ディープリンクURLが無効化された場合は、アプリ内の設定画面からURLを更新できるようにする

## 6. スコープ外(v1では対応しない)

- 銀行API/オープンバンキング連携による完全自動取得
- 複数ユーザー対応・App Store配布
- Android対応
- Share Extensionによる自動取り込み(将来検討、まずは手動インポート画面で実装)
- ログイン自動化・画面操作の自動化(JavaScript注入等)
