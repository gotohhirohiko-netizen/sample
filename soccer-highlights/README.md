# サッカーハイライト作成ツール

YouTubeにアップロードされた試合動画を見ながら「開始〜終了」のタイムスタンプでシーンをタグ付けし、
切り抜き・並べ替え・結合・(必要なら)音楽への差し替えを行ってハイライト動画を作るためのツール。

`web/`(家計簿PWA)や`child-tasklist/`とは異なり、**GitHub Pagesにはデプロイしないローカル専用アプリ**。
YouTube動画のダウンロードや動画の切り抜き・結合には`yt-dlp`と`ffmpeg`が必要で、これらはブラウザ内(静的サイト)
だけでは実行できないため、ローカルで動くExpressサーバーを併用する構成になっている。

## できること

- YouTubeの動画をブラウザ埋め込みプレーヤーで再生しながら、現在の再生位置で「区間開始」「区間終了」を押してクリップをタグ付け
- 複数のYouTube URLを読み込んで、それぞれから別々にクリップを切り出し可能
- クリップの一覧表示、順序の入れ替え(↑↓)、削除、ラベル編集
- プロジェクト名を付けてクリップ一覧・読み込んだ再生リストを保存(`data/projects/`)。編集すると自動保存
  され(チェックボックスでオン/オフ可)、「今すぐ保存」ボタンも用意。プロジェクトを開くと再生リストも
  自動的に再読み込みされる
- クリップを指定順に結合してハイライト動画を書き出し、ローカル(`data/output/`)に保存。この「結合済み動画」は
  プロジェクトに記憶され、あとから何度でも呼び出して音楽を追加し直せる
- 複数のmp3を指定した順番で連結して音声トラックとして適用可能。選んだmp3の合計時間が動画の長さに対して
  足りているか不足しているかを表示しながら追加・削除・並べ替えできる
- 書き出した動画をYouTubeにアップロード(非公開/限定公開/公開を選択可)

## 前提ソフトウェア(事前にインストールが必要)

- Node.js 22系(`web/`と同じ)
- [ffmpeg](https://ffmpeg.org/download.html)(切り抜き・結合・音声差し替えに使用)
  - macOS: `brew install ffmpeg`
  - Windows: `winget install ffmpeg` または公式サイトからバイナリ取得しPATHに追加
  - Linux: `sudo apt install ffmpeg` 等
- [yt-dlp](https://github.com/yt-dlp/yt-dlp#installation)(YouTube動画のダウンロードに使用)
  - macOS: `brew install yt-dlp`
  - Windows: `winget install yt-dlp`
  - Linux/pip: `pip install -U yt-dlp`
  - YouTube側の仕様変更で失敗するようになった場合は `yt-dlp -U` で更新する

いずれもコマンドラインで `ffmpeg -version` / `yt-dlp --version` が通ることを確認してから使うこと。

### `HTTP Error 403: Forbidden` が出る場合

`yt-dlp -U` で最新版にしても解消しない場合、YouTube側が「ログイン状態でないとダウンロードさせない」
制限をかけている動画である可能性が高い。その場合はブラウザのCookieを使ってyt-dlpにログイン状態を
渡す必要がある。

1. 普段YouTubeを見ているブラウザで、一度その動画(または同じチャンネルの動画)を開いてログインしておく
2. `soccer-highlights/.env` に以下を追加(`.env.example`にひな形あり)

   ```
   YTDLP_COOKIES_FROM_BROWSER=chrome
   ```

   Edgeなら`edge`、Firefoxなら`firefox`。複数プロファイルを使い分けている場合は
   `chrome:Default` のようにプロファイル名も指定する。
3. サーバー(`npm run dev` / `npm start`)を再起動する
4. ブラウザ側でCookieファイルがロックされて読めないことがあるため、ダウンロードが失敗する場合は
   一度そのブラウザを閉じてから試す

## セットアップ

```bash
cd soccer-highlights
npm install
```

## 開発時の起動(2プロセス: フロントエンド + APIサーバー)

```bash
npm run dev
```

- フロントエンド(Vite): http://localhost:5173 を開く
- APIサーバー(Express): http://localhost:8787 で待ち受け、Viteが`/api`をここにプロキシする

## ローカルでの本番相当起動(1プロセス)

```bash
npm run build
npm start
```

http://localhost:8787 を開く(ビルド済みフロントエンドをExpressが配信し、同じプロセスでAPIも動く)。

## 使い方

1. 「プロジェクト」欄でプロジェクト名を入力する(例: 「8/10 練習試合」)。名前を付けると
   「自動保存を有効にする」がオンの間、クリップの追加・並べ替え・削除のたびに自動保存される。
   クリップ数はプロジェクト欄の見出しに常に表示される。自動保存をオフにした場合は、保存済みの
   クリップ数と現在のクリップ数を比較して「保存が必要です」のように表示されるので、「今すぐ保存」
   ボタンで手動保存する
2. 試合動画のYouTube URLを貼り付けて「読み込む」(再生リストのURLを左メニューで読み込んで、
   そこから動画を選ぶこともできる)
3. 動画を再生しながら見たい場面で「区間開始」→ 該当シーンの終わりで「区間終了してクリップ追加」
4. 別のYouTube URL(別の試合・別アングルなど)を読み込むと、続けてそこからもクリップを追加できる
5. クリップ一覧で順序を↑↓で入れ替え、不要なものは削除、名前も編集可能
6. 作業を中断・再開したいときは「プロジェクト」欄の「保存済みプロジェクトを開く」から選び直せる。
   途中で不安なら「今すぐ保存」ボタンでいつでも即時保存できる
7. 「書き出し(切り抜き・結合)」でファイル名を入力して「結合して書き出し」
   - 元動画のダウンロード → 各クリップの切り出し → 結合、の順に進み進捗が表示される(この時点では
     音声は元のまま)
   - 処理が重い・想定より時間がかかる等の理由で途中でやめたい場合は「キャンセル」ボタンで中止できる
     (ここまでの処理内容は破棄され、一時停止からの再開はできない)
   - 完了すると`data/output/`にmp4として保存され、その結合済み動画がプロジェクトに記憶される
8. 音楽を追加したい場合は、その下の「音楽を追加」でmp3を選ぶ(複数選択・複数回の追加が可能。選んだ順に
   連結される)。「↑↓」で順序変更、「削除」で個別に外せる。合計時間が動画の長さに対して足りているか
   不足しているかがその場で表示される(不足分は無音になる、超過分は自動的に切り詰められる)。ファイル名を
   指定して「音声を適用して書き出し」を押すと、結合済み動画に対してだけ音声を差し替えるため、切り抜き・
   結合からのやり直しは不要で短時間で終わる。同じ結合済み動画に対して、別の曲の組み合わせで何度でも
   試すことができる
9. そのままYouTubeにアップロードする場合は、各処理の完了後に表示される「YouTubeにアップロード」パネルを
   使う(初回は認証設定が必要。下記参照)

## YouTubeアップロード設定(任意)

書き出した動画をアプリから直接YouTubeにアップロードしたい場合のみ設定する。ローカル保存だけで良ければ不要。

1. [Google Cloud Console](https://console.cloud.google.com/)でプロジェクトを作成
2. 「APIとサービス」→「ライブラリ」で **YouTube Data API v3** を有効化
3. 「APIとサービス」→「OAuth同意画面」を設定(テストユーザーとして自分のGoogleアカウントを追加すればOK。外部公開審査は不要)
4. 「認証情報」→「OAuthクライアントID」を作成(アプリケーションの種類: ウェブアプリケーション)
   - 承認済みのリダイレクトURIに `http://localhost:8787/api/youtube/oauth2callback` を追加
5. 発行された「クライアントID」「クライアントシークレット」を`soccer-highlights/.env`に設定
   (`.env.example`をコピーして使う)

   ```bash
   cp .env.example .env
   # .env を編集してGOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET を入力
   ```

6. アプリの書き出し完了後、「YouTubeにログイン」ボタンから認証(初回のみ)。認証情報は
   `data/youtube-token.json`にローカル保存される(Gitには含めない)

## 注意事項

- **著作権・利用規約**: 自分の子供の試合を自分でYouTubeに投稿した動画をダウンロードして個人用ハイライトを
  作る分には実用上問題になりにくいが、YouTube利用規約上、動画のダウンロード自体はグレーな行為とされている。
  他人が撮影・投稿した動画や、著作権のある音楽をBGMとして使う場合は権利関係に注意すること。
- クリップの切り抜きはフレーム精度のため**再エンコード**を行う(コピーだけの結合より時間がかかる)。
  試合動画が長い・クリップ数が多いほど書き出しに時間がかかる。「音楽を追加」側は映像を再エンコードしない
  (`-c:v copy`)ため、こちらは比較的すぐ終わる。
- 音声差し替えは動画の音声トラックを丸ごとmp3に置き換える(元の実況・歓声などは残らない)。
- プロジェクト名を変更すると、新しい名前で別ファイルとして保存される(元の名前のファイルはそのまま
  `data/projects/`に残る)。同じプロジェクトとして続けたい場合は名前を変えないこと。
- 「音楽を追加」欄に表示される結合済み動画の情報(クリップ数・長さ)と、現在のクリップ一覧が食い違って
  いる場合は警告が出る(結合後にクリップを編集した場合など)。その場合は「書き出し(切り抜き・結合)」を
  やり直して最新の内容で結合し直すこと。
- 結合済み動画(`data/output/`内)はダウンロード元動画のキャッシュとは異なり自動削除されない。何度も
  音楽を差し替えて試せるようにするための仕様だが、不要になったら手動で削除すること。
- ダウンロードした元動画(`data/downloads/`)は書き出しジョブの中でその動画を使う最後のクリップの
  切り出しが終わった時点で自動的に削除される。試合動画は1本あたり数百MB〜になるため、ジョブをまたいで
  ディスクに溜め込まないようにしている。同じ動画から複数回に分けて書き出す場合は、その都度ダウンロード
  し直しになる点に注意。
- **空き容量チェック**: `data/`のあるドライブの空き容量が既定で3GBを下回ると、書き出しを開始できない、
  または処理の途中でも中断してエラー表示される(ダウンロード・切り出しの各ステップの前にチェックする)。
  しきい値は環境変数`MIN_FREE_DISK_GB`で変更できる(`.env`に`MIN_FREE_DISK_GB=5`のように設定)。
  「書き出し」パネルには現在のPCの空き容量が常に表示される。

## ディレクトリ構成

```
soccer-highlights/
  src/                       フロントエンド(React)
    components/              YouTubeプレーヤー、クリップタグ付け、一覧、書き出しパネル等
    lib/                     API呼び出し、YouTube IFrame API読み込み
  server/src/                バックエンド(Express)
    routes/                  /api/sources, /api/export, /api/output, /api/youtube, /api/projects
    lib/                     yt-dlp/ffmpeg呼び出し、ジョブ進捗管理、YouTube OAuth
  data/                      実行時に生成(Git管理外)
    downloads/                yt-dlpでダウンロードした元動画のキャッシュ(videoId単位、使い終わると自動削除)
    output/                   書き出し済みの結合済み動画・音声適用済み動画(ローカル保存先、自動削除されない)
    projects/                 保存したクリップ一覧・再生リスト・結合済み動画の参照(プロジェクト名ごとのJSON)
    tmp/                      書き出し処理中の一時ファイル
```
